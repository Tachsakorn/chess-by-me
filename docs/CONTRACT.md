# สัญญาของผลวิเคราะห์ (ฉบับอ่านง่าย)

สถานะ: **เจ้าของอนุมัติแล้วเมื่อ 2026-11-13** (แก้ไขต้องขออนุมัติใหม่) · ตัวจริงอยู่ที่ `src/contract/types.ts` · เวอร์ชันสัญญา: 1

## สัญญาคืออะไร และทำไมต้องอนุมัติ

แอปมีสองฝั่ง ฝั่ง "ระบบ" คิดคำนวณ (ดึงเกม รัน Stockfish จัดหมวดตา) ฝั่ง "หน้าจอ" แสดงผล
สัญญาคือรายการที่ตกลงกันว่า ระบบจะส่งข้อมูลอะไรให้หน้าจอ ในรูปแบบไหน
เมื่อสัญญานิ่งแล้ว subagent หลายตัวสร้างฝั่งระบบพร้อมกันได้ และผมสร้างหน้าจอคู่ขนานไปได้ โดยไม่มีใครต้องรอใคร
ถ้าแก้สัญญาทีหลัง งานทั้งสองฝั่งต้องแก้ตาม จึงอยากให้เจ้าของเห็นก่อนว่ามีอะไรบ้าง

## ข้อตกลงพื้นฐาน

- ค่าประเมินทุกค่ามองจากฝั่งขาวเสมอ ไม่ว่าตาใครเดิน
- โอกาสชนะเป็นเลข 0 ถึง 1 (1 = ขาวชนะ) ความแม่นเป็น 0 ถึง 100
- ในสัญญาไม่มีข้อความที่แสดงให้ผู้ใช้เห็น มีแต่ "รหัส" แล้วหน้าจอแปลงเป็นคำตามภาษา ทำให้เพิ่มภาษาได้โดยไม่แตะระบบ

## ข้อมูลที่ระบบส่งให้หน้าจอ

**1. เกมหนึ่งเกม** (ก่อนวิเคราะห์)
ที่มา (Chess.com / Lichess / PGN) ลิงก์กลับไปเกมต้นทาง วันเวลา ชื่อ เรตติ้ง และตำแหน่ง (เช่น IM) ของผู้เล่นสองฝั่ง
ผลเกม วิธีจบเกม (รุกจน ยอมแพ้ หมดเวลา เสมอแบบต่างๆ) รูปแบบเวลา และตาเดินทุกตา
แต่ละตาเดินมี: สัญลักษณ์ตาเดิน ตำแหน่งกระดานก่อนและหลัง เวลาที่เหลือบนนาฬิกา และเวลาที่ใช้คิดตานั้น

**2. ผลนำเข้าเกม**
สำเร็จ: รายการเกม (ใหม่สุดก่อน) และจำนวนเกมที่ข้ามไปเพราะไม่ใช่หมากรุกมาตรฐาน
ไม่สำเร็จ: รหัสสาเหตุ เช่น ไม่พบผู้ใช้ ไม่มีเกม PGN ผิดรูปแบบ ถูกจำกัดความถี่ เน็ตมีปัญหา

**3. ค่าประเมินของแต่ละตำแหน่ง**
คะแนน (เป็นเบี้ย หรือ "รุกจนใน N ตา" หรือ "เกมจบแล้ว") โอกาสชนะของขาว (ใช้วาดกราฟและแถบ eval)
ความลึกที่ค้น แนวทางที่ดีที่สุด 1-2 แนว และที่มาของค่า (engine ในเครื่อง / Lichess cloud / ตัดสินจากกติกา)

**4. รีวิวของแต่ละตาเดิน**
หมวดตา (Brilliant, Great, Best, Excellent, Good, Book, Inaccuracy, Mistake, Miss, Blunder)
โอกาสชนะที่เสียไปจากตานี้ ความแม่นของตานี้ ตาที่ดีที่สุดคืออะไร และตาที่เดินตรงกับตาที่ดีที่สุดไหม
พร้อม "ป้ายเหตุผล" สำหรับคำอธิบายสั้นใต้ตาปัจจุบัน เช่น สละหมาก, เป็นตาเดียวที่ดี, ตาบังคับ, พลาดรุกจน, พลาดโอกาสชนะ, เปิดทางให้ถูกรุกจน, ทิ้งความได้เปรียบ

**5. สรุปทั้งเกม**
engine ที่ใช้และความลึก ชื่อเปิดหมากพร้อมรหัส ECO และตาสุดท้ายที่ยังอยู่ในตำรา
ของผู้เล่นแต่ละฝั่ง: ความแม่นรวม เรตติ้งประมาณการ **เป็นช่วงเสมอ** (สัญญาไม่มีช่องให้ใส่เลขเดียว) และจำนวนตาในแต่ละหมวด

**6. เหตุการณ์ระหว่างวิเคราะห์** (ทำให้ผลไหลเข้ามาทีละตา)
เริ่ม → กำลังโหลด engine (กี่ไบต์จากกี่ไบต์) → ได้ค่าของตำแหน่งที่ N จากทั้งหมด M (ความคืบหน้าจริง) → ได้รีวิวของตา → ได้ชื่อเปิดหมาก → เสร็จ หรือ ล้มเหลวพร้อมรหัสสาเหตุ
ผู้ใช้ยกเลิกกลางทางได้

## กติกาที่ตัวตรวจบังคับอัตโนมัติ

ผลวิเคราะห์ทุกชุดต้องผ่านตัวตรวจ (`validateGameAnalysis`) ซึ่งมีเทสต์ 10 ข้อ เช่น
จำนวนตำแหน่งต้องเท่ากับจำนวนตา + 1, ตำแหน่งต้องตรงกับเกมจริง, ตัวเลขต้องอยู่ในช่วง,
เรตติ้งต้องเป็นช่วงที่ค่าต่ำน้อยกว่าค่าสูง, จำนวนตาในแต่ละหมวดต้องตรงกับรายการตาจริง,
ป้าย Book ต้องใช้กับตาในตำราเท่านั้น

## สิ่งที่สัญญานี้ยังไม่ครอบคลุม (ตั้งใจ)

- คำอธิบายแบบโค้ช และโหมดฝึกซ้ำตาที่พลาด (บรีฟบอกว่ายังไม่ทำ)
- หมากรุกรูปแบบอื่น เช่น Chess960
- ลูกศรหรือการไฮไลต์ช่องบนกระดาน: หน้าจอวาดเองจากตาที่ดีที่สุดที่มีอยู่แล้ว

การเพิ่มช่องข้อมูลใหม่ทีหลังทำได้โดยไม่กระทบงานเดิม แต่การเปลี่ยนชื่อ ลบ หรือเปลี่ยนความหมายของช่องเดิมต้องขออนุมัติใหม่
